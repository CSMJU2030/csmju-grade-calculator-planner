# บันทึกรายการคะแนนของรายวิชา

ชุดนี้เพิ่มการจัดการคะแนนที่บันทึกลงฐานข้อมูลผ่าน API ของ NestJS ที่มีอยู่แล้ว
ไม่เปลี่ยน schema, migration, auth, permissions, dependencies หรือไฟล์ deploy
ไม่แก้ไฟล์ `frontend/src/csmju/` และ `globals.css`

## ใช้งาน

1. เข้าสู่ระบบด้วย Core Hub แล้วเปิด รายวิชา → บันทึกคะแนน
2. เลือกรายวิชา หรือเปิดหน้าคำนวณเกรดแล้วเลือกวิชา
3. ส่วน **คะแนนที่บันทึกในรายวิชา**: กรอกชื่อรายการ คะแนนเต็ม น้ำหนัก และคะแนนที่ได้
   คะแนนว่างบันทึกเป็น `null` (ยังไม่ประกาศ); ค่า 0 บันทึกเป็นศูนย์จริง
4. กด บันทึก แล้วรีเฟรช: ระบบโหลดคะแนนจากฐานข้อมูลกลับมา
5. ปุ่ม แก้ไข โหลดรายการเดิมเข้าฟอร์ม; การบันทึกแก้รายการเดิม ไม่สร้างซ้ำ
6. ปุ่ม ลบ ต้องยืนยันชื่อรายการก่อนลบ และเปลี่ยนผลคำนวณตามข้อมูลที่เหลือ
7. ปุ่ม วางแผนเกรดวิชานี้ เปิดวิชาเดียวกันโดยอ่านคะแนนที่บันทึกแล้ว

ส่วน **ทดลองคำนวณและประมาณคะแนน** ยังเป็นร่างสำหรับจำลองเท่านั้น
ยังไม่ส่งร่างหรือค่าประมาณไปฐานข้อมูล และไม่ปะปนกับรายการคะแนนจริง
การบันทึกกลุ่มประมาณพร้อมข้อมูลแหล่งที่มา/การคำนวณใหม่เป็นงานถัดไป

## ตัวอย่างตรวจรับ

สร้างสองรายการในรายวิชาทดสอบ:

- Midterm: ได้ 18 เต็ม 20 น้ำหนัก 30 → คะแนนสะสม 27
- Final: เว้นคะแนนว่าง เต็ม 100 น้ำหนัก 70 → ยังไม่ทราบคะแนน

เป้าหมาย A (80): ต้องทำ Final เฉลี่ยประมาณ 75.71%
ทั้งหน้าคำนวณคะแนนที่บันทึกและหน้าวางแผนต้องให้ผลเดียวกัน
แก้ Final เป็น 80: คะแนนสะสม 83 เกรด A; ต้องทำเพิ่ม 0%
แก้ Final เป็น 0: คะแนนสะสม 27 และนับว่า Final ทราบคะแนนแล้ว
แก้ Final กลับเป็นว่าง: คะแนนสะสม 27 และเหลือน้ำหนักไม่ทราบ 70%
รีเฟรชหลังแต่ละการเปลี่ยนแล้วตรวจข้อมูลยังอยู่
ลบ Final แล้วยืนยันว่าโหลดใหม่ไม่พบรายการนั้น

## การตรวจและข้อจำกัด

- UI ซ่อนปุ่มตาม permissions เดิม; NestJS ยังคงตรวจ JWT/role/owner จริงทุกคำขอ
- Proxy ส่ง HttpOnly cookie ไป backend และปฏิเสธ cross-origin mutations
- API wrapper ใช้ `no-store`; ไม่เก็บ token ใน browser storage
- การบันทึกที่ล้มเหลวไม่ล้างฟอร์ม และไม่แสดงว่าบันทึกสำเร็จ
- ป้องกันกดบันทึก/ลบซ้ำขณะที่คำขอยังทำงาน
- ฝั่ง backend ตรวจ score/maxScore/weight ของรายการสุดท้ายหลัง merge PATCH
  จึงห้ามคะแนนเกินคะแนนเต็ม รวมถึงการลดคะแนนเต็มต่ำกว่าคะแนนเดิม
- น้ำหนักรวม 100% ตรวจฝั่งฟอร์มจากรายการที่โหลด; ไม่ใช่ข้อบังคับแบบ transaction
  สำหรับหลายหน้าที่แก้พร้อมกัน ให้โหลดใหม่และตรวจน้ำหนักรวมอีกครั้ง
  การบังคับผลรวมน้ำหนักพร้อม concurrency ระดับฐานข้อมูลยังเป็นงานถัดไป
- ไม่เปลี่ยนสิทธิ์เพิ่มรายวิชาของนักศึกษา; ต้องยืนยัน G0 กับ PL
- ยังไม่ได้เพิ่ม GPA, attendance/type หรือการเชื่อมทะเบียนรายวิชากลางในชุดนี้
- ไม่อ้างผล SSO/ฐานข้อมูลจริงหรือ full build จากเครื่องเตรียมชุดแก้

## ตรวจบนเครื่องทีมก่อน commit

รัน `./standards/scripts/run-all-checks.sh .`
หากใช้ Docker รัน `docker compose up -d --build --wait --wait-timeout 180`
เพื่อให้ container ใช้โค้ดใหม่โดยไม่ลบ volume ฐานข้อมูล
ทดสอบตัวอย่างด้านบนด้วย session จริงหลังทะเบียนระบบพร้อม
ห้ามใช้ bypass login

ชุดนี้เพิ่ม regression tests ของ backend 9 กรณี
ตรวจ invalid create, partial PATCH, 0/null และเกรดเป้าหมายที่ถึงแล้ว
ผล Jest/build/CI ของชุดใหม่ต้องยืนยันบนเครื่องทีมก่อนบันทึกใน REPORT.md

- TypeScript strict ของ frontend จาก source snapshot พร้อม Next.js 16.3.6,
  React 19.2.8 และ route types ที่สร้างด้วย `next typegen`: ผ่าน
- Frontend ESLint ตาม config เดิม: ผ่านหลังแก้คำเตือนเรื่อง ref cleanup
- Backend Jest: รันสอง suites ที่แก้ ผ่าน 28 tests (19 เดิม + 9 ใหม่)
  ใช้โค้ด transpile ของ service จริงกับ mock Prisma; ไม่ได้รันทั้ง 7 suites ในเครื่องนี้
- Proxy/form/calculation harness: ผ่าน same-origin, UUID/body validation,
  cookie forwarding, sanitized payload, 0/null และตัวอย่างคะแนน 27/83
- Installer fixtures: ผ่าน preflight/install/idempotence/restore/conflict/symlink
  และตรวจว่าไฟล์นอกชุดแก้รวม auth/schema/ส่วนกลางไม่เปลี่ยน
- Full Next/Nest build, run-all-checks และ Docker runtime ของชุดใหม่นี้
  ยังต้องยืนยันบนเครื่องทีม ไม่ใช้ผลชุดก่อนแทนผลชุดนี้
